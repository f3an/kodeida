# Кодеїда — технічний план MVP

> Стан на 2026-10-15. Застосунок лежить у [`app/`](../app). Готовий вміст MVP: онбординг і світи 0–2 (22 вправи),
> українська й англійська. Інсталятори для трьох ОС і автооновлення працюють, випущено [0.1.0 і 0.1.1](https://github.com/f3an/kodeida/releases).
> Наступний крок — тест на людях. Ідея й рішення описані в [NOTES.md](NOTES.md).

## 2. Головне рішення: код гравця — це звичайний код задачі

Найбільший ризик ([NOTES.md, «Ризики»](NOTES.md#ризики)) — API світу, яке робить прийом непотрібним. Наприклад,
`world.fill(l, r)`, що сам рахує площу, або `enei.moveToBest()`.

Тому у фінальних задачах і більшості вправ **гравець пише функцію з тим самим підписом, що на LeetCode**:

```ts
function maxArea(height: number[]): number { … }
```

Світ не дає жодних «розумних» команд. Він **спостерігає** за кодом: вхідні дані загорнуто в спостережувані обгортки
(`Proxy`), і кожне читання `height[i]` стає подією в лозі. Анімація показує, куди дивиться код: Еней і Микита
стають біля стовпів, які щойно прочитано, а між ними набирається вода. Два вказівники видно самі собою, бо читання
сходяться з двох кінців; Вовчий перебір видно так само, як нескінченне снування від стовпа до стовпа.

Наслідки:

- навичка переноситься на LeetCode **без перекладу**: те саме рішення можна вставити туди;
- **ціна рішення = кількість читань даних**, а не мілісекунди. Порівняння з Вовком детерміноване й не залежить від
  швидкості комп'ютера: для n = 10 000 Микита читає ~2n разів, Вовк — ~n²;
- явні команди (`enei.move()`) лишаються тільки в онбордингу і перших вправах світу 0, де ще вчимо цикл і умову.
  Там API навмисно «тупе»: один крок, один мішок.

## 3. Пайплайн «код → лог подій → анімація»

```
Monaco ──код──▶ runner.ts ──▶ Web Worker (пісочниця)
                  │  таймаут      │ 1. TS → JS (sucrase, лише зняття типів, рядки не зсуваються)
                  │  terminate()  │ 2. вимкнути мережу й importScripts
                  │               │ 3. виконати код, обгорнути вхід у Proxy
                  │               │ 4. зібрати лог подій, console.log, результат, помилку з рядком
                  ◀───результат───┘
       │
       ├─▶ Суд богів: порівняти з очікуваними відповідями, бюджет читань → вердикт
       └─▶ World canvas: програти лог подія за подією (швидкість, крок, пауза)
```

### 3.1 Пісочниця

- Кожен запуск — **новий Worker**: стан між запусками не тече, а зависання лікується `worker.terminate()`.
- **Таймаут** 2 с на запуск (нескінченний цикл → «Юнона: шторм ще не скінчився»), окремо **бюджет подій** (лог не
  росте безмежно, ліміт 20 000 подій для анімації).
- Перед виконанням у Worker'і видаляються `fetch`, `XMLHttpRequest`, `WebSocket`, `importScripts`, `indexedDB`.
  У Electron діє CSP без мережі, `contextIsolation`, без `nodeIntegration`.
- Код компілюється через `(0, eval)` з `//# sourceURL=slovo.js`, тож рядок помилки береться зі стеку без зсувів:
  «Еней спіткнувся на рядку 12: right is not defined».

### 3.2 Лог подій

Плаский масив JSON-подій, однаковий для будь-якої мови (для Python потрібен лише новий раннер на Pyodide):

```ts
type WorldEvent =
  | { t: 'read'; arr: string; i: number }          // код прочитав елемент
  | { t: 'write'; arr: string; i: number; v: unknown }
  | { t: 'log'; text: string }                     // console.log гравця
  | { t: 'act'; name: string; args: unknown[] };   // явні команди онбордингу: move, take, …
```

Світ сам вирішує, як показати подію. Карфаген: `read` → герой іде до стовпа `i`; дві останні різні позиції
читання — це «лівий» і «правий» кінці, між ними вода і площа.

### 3.3 Суд богів (тести)

Рівень описує:

- **приклади** — малі входи, видимі гравцю; перший з них програється анімацією;
- **приховані тести** — граничні випадки (два стовпи, однакові висоти, спадання, нулі);
- **великий тест** — n = 10 000 з **бюджетом читань** (для Дидони 10n — з запасом для будь-якого O(n), а Вовкові потрібно n²). Перевищив бюджет — вердикт
  «Вовче рішення»: відповідь правильна, але Вовк би так і зробив.

Вердикти: ✅ «По-лисячому» · 🐺 «Працює, але повільно» · ❌ «Неправильна відповідь» · ⛈ «Час вийшов» ·
💥 «Помилка на рядку N».

### 3.4 Порівняння з Вовком

Після Суду богів гравець бачить свою кількість читань поруч з Вовчою (перебір усіх пар, n(n−1)) для n = 10, 100,
10 000. Це наочна O(n) проти O(n²) без формул; формули — у Книзі хитрощів.

## 4. Формат рівня

```ts
interface Level {
  id: string;                       // 'carthage.dido'
  world: number;                    // 2
  title: string; story: string;     // українською, Markdown
  entry: string;                    // ім'я функції гравця: 'maxArea'
  starter: { ts: string; js: string };
  examples: TestCase[];             // видимі
  hidden: TestCase[];               // приховані
  big?: { make: () => TestCase; readBudget: (n: number) => number };
  wolfReads: (n: number) => number; // скільки читань робить Вовк
  hints: [string, string, string];  // Сивілла: натяк → ідея → псевдокод
  scene: 'carthage';                // який світ малює лог
}
```

Рівні — це дані (TypeScript-модулі в `app/src/levels`), тож новий світ = новий модуль рівнів + новий рендерер сцени.

## 5. Структура коду

```
app/
  electron/main.cjs        вікно Electron, протокол app:// з CSP, меню, без nodeIntegration
  electron/preload.cjs     міст: версія, мова, оновлення
  electron/updater.cjs     electron-updater: перевірка, завантаження, діалоги «Перевірити оновлення…»
  build/                   іконка й entitlements для electron-builder
  src/
    engine/                типи, раннер, Worker-пісочниця, суддя — без React і canvas
    levels/                світи 0–2 як дані, англійські тексти (en.ts), Книга хитрощів
    world/sprites.js       ЗГЕНЕРОВАНО з site/app.js: рушій, герої, заставки, мапа мандрівки
    world/scenes.ts        сцени вправ: масив (ArrayScene) і вулиця з командами Енея (StreetScene)
    ui/                    React: меню, онбординг, тур Сивілли, рівень, мапа, книга, вишиванка, налаштування
    i18n.ts                L('укр', 'eng') і переклад написів на полотні
  scripts/selftest.mjs     рушій і кожна вправа: лисяче рішення проходить, вовче — ні (CI)
  scripts/sync-sprites.mjs site/app.js → src/world/sprites.js
```

Піксельний рушій, герої, заставки й мапа живуть у `site/app.js`, а гра копіює їх командою `npm run sync-sprites`,
тож сайт і гра виглядають однаково. Рушій малює спрайт один раз у `ImageData`, далі — одним `drawImage` з масштабом.

## 5.1 Релізи й оновлення

- `npm run dist` — інсталятор для поточної ОС у `app/release/`.
- Тег `vX.Y.Z` → [`.github/workflows/release.yml`](../.github/workflows/release.yml) збирає macOS (`.dmg`, `.zip` для Apple Silicon і Intel),
  Windows (NSIS) і Linux (AppImage) і публікує GitHub Release з `latest*.yml`. Ручний запуск лише збирає.
- Встановлена гра перевіряє оновлення під час запуску, кожні 6 годин, з меню й налаштувань; завантажує у фоні
  (або за кнопкою, якщо автозавантаження вимкнене) і ставить після перезапуску.
- macOS підписується й нотаризується, коли в репозиторії задано секрети (див. CONTRIBUTING.md → Releases);
  без підпису на Mac немає автооновлення.
