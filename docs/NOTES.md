## Ідея

Гейміфікована програма рівня Swift Playgrounds, яка вчить розв'язувати задачі рівня
LeetCode / Codewars / HackerRank.

- **Зліва** — інтерфейс у стилі VS Code (редактор, вкладки, підказки, опис задачі), **без AI-тулзів**.
- **Справа** — ігровий світ: код, який пише користувач, керує тим, що відбувається на екрані
  (персонаж ходить, збирає предмети, сортує ящики тощо).
- **Мета** — навчити *правильно застосовувати потрібні прийоми й алгоритми в потрібних ситуаціях*,
  а не просто «здати задачу».

## Мови

TypeScript, JavaScript, Python, C#, C++, Go, … 

## Прийняті рішення

1. **Платформа:** десктоп — **Electron** + React + Vite + TypeScript.
   - Electron, бо Node вже стоїть; Tauri потребує Rust. (Можна переглянути.)
   - Редактор — **Monaco** (рушій VS Code).
2. **Виконання коду:** спершу **в браузерному рушії** всередині застосунку.
   - JS / TS — нативно (TS транспілюється в JS).
   - Python — **Pyodide** (WASM).
   - C# / C++ / Go — пізніше, окремим сервісом-пісочницею (Docker-раннер у стилі Piston/Judge0)
     або локальними компіляторами через Electron main-процес.
3. **Тека проєкту:** `~/work/algo-quest`.

## Архітектура (план)

```
┌──────────────── Electron window ────────────────┐
│  Ліва панель (Monaco)  │  Права панель (canvas)  │
│  - умова задачі        │  - сітка/світ           │
│  - вибір мови          │  - персонаж, об'єкти    │
│  - Run / Step / Reset  │  - програвання подій    │
│  - тести, підказки     │  - покроковий режим     │
└─────────────────────────────────────────────────┘
          │ код                     ▲ лог подій
          ▼                         │
   Web Worker (sandbox, таймаут) ───┘
```

- **Runner** — код виконується в Web Worker з таймаутом (нескінченний цикл не вішає застосунок).
- **World API** — кожна задача надає світу своє API, напр. `hero.move()`, `hero.pick()`, `grid.get(x, y)`.
- **Event log** — під час виконання збирається лог подій → права панель програє його як анімацію.
  Завдяки цьому логіка однакова для всіх мов: для нової мови треба лише новий раннер.
- **Перевірка рішення:**
  - тести як на LeetCode (вхід → очікуваний вихід);
  - перевірка «чи використано потрібний прийом» — лічильник операцій / доступів до масиву
    (напр. показати, що рішення O(n²), коли очікується O(n)).
- **Прогрес** — зірки/рівні, зберігаються локально.

## Структура контенту (MVP)

Розділ = один прийом. Усередині: 3–4 підвідні вправи в ігровому світі → фінальна справжня задача.

Приклад розділу **«Два вказівники»**:
1. Вправи: два персонажі йдуть назустріч по ряду клітинок, міняються предметами, зупиняються в потрібній точці.
2. Фінальні задачі: Two Sum II, Valid Palindrome, Container With Most Water.

Кандидати на наступні розділи: Sliding Window, Hash Map / підрахунок частот, Prefix Sum,
Binary Search, Stack, BFS/DFS на сітці, Fast & Slow pointers.

## Бренд і маскот: українська ідентичність

Спільне для всіх концепцій: **візуальний стиль у дусі вишивки**. Хрестикова вишивка — це, по суті,
піксель-арт на сітці, тому вона природно лягає на ігрову сітку, спрайти й іконки. Орнаменти — це
«патерни», так само як прийоми в алгоритмах.

### Концепція A: Січ / Козак (фаворит)
- **Маскот:** юний козак-програміст з оселедцем; оселедець можна стилізувати під `{`.
- **Назви:** **Kodzak** (код + козак), **CodeSich**, **Січ.код**.
  - ⚠️ Kodzak звучить близько до Kodak, тому торгову марку треба перевірити.
- **Світ:** степ, Дніпро, Січ. **Розділи — це дніпровські пороги**: кожен поріг відповідає
  одному прийому, а фінальна задача розділу — «пройти поріг».
- **Ранги прогресу:** джура → козак → десятник → сотник → осавул → полковник → гетьман.

### Концепція B: Чумацький шлях
- **Маскот:** віл-чумак, повільний, але розумний (легко пожартувати про O(n²)).
- **Назва:** **Chumak** / **Чумацький шлях**.
- **Ідея:** чумаки шукали найкоротші й найвигідніші маршрути, що прямо відповідає графам, BFS/DFS
  і Dijkstra. «Чумацький шлях» — це ще й Молочний Шлях: зірки за рішення збираються в сузір'я.

### Концепція C: Вулик
- **Маскот:** бджілка.
- **Назва:** **Vulyk** / **Вулик**.
- **Ідея:** світ на шестикутних сотах (графи, обхід, пошук шляху); бджола збирає пилок — це
  задачі на оптимізацію. Мирний і дружній тон, підходить для широкої аудиторії.

### Концепція D: Мольфар
- **Маскот:** юний мольфар-учень із Карпат.
- **Назва:** **Molfar**.
- **Ідея:** код — це заклинання, функції — закляття, які можна вивчити й поєднувати. Світ: гори,
  полонини, трембіта як сигнал старту. Розділи — гірські вершини. Дуже природно для RPG-гейміфікації.

### Концепція E: Соняшник
- **Маскот:** соняшник або горобчик на соняшнику.
- **Назва:** **Sonyakh** / **Sunflower**.
- **Ідея:** насіння в соняшнику розміщене спіраллю Фібоначчі — це прямий вхід у рекурсію та DP.
  Поле соняшників — сітка рівнів. Світлий, впізнаваний у світі символ України.

### Концепція F: Борщ (алгоритм = рецепт)
- **Маскот:** буряк-кухар (або бабуся-шеф).
- **Назва:** **Borshch** / **Algorshch**.
- **Ідея:** класичне пояснення «алгоритм — це рецепт». Кухня: черга замовлень (queue), стос тарілок
  (stack), сортування інгредієнтів. Смішно, меметично, добре для маркетингу.

### Концепція G: Лелека
- **Маскот:** лелека.
- **Назва:** **Leleka**.
- **Ідея:** гнізда на стовпах — дерева як структура даних; перельоти — графи й маршрути.
  Символ дому й повернення: «повертайся щодня» для стріків.

### Концепція H: Писанка / Петриківка
- **Маскот:** петриківський півник.
- **Назва:** **Pysanka**, **Petryk**.
- **Ідея:** кожен опанований прийом — розписана писанка в колекції (бейджі). Петриківські гілки ростуть
  рекурсивно, тож дерева рекурсії малюються як розпис.
